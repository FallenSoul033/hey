# IceFresh.kz — Release Candidate 1

Версия: `12.0.0-rc.1`

Это Release Candidate, подготовленный после IT-аудита версии 12. Он **не опубликован на icefresh.kz и не применён к рабочей Supabase**. Цель RC1 — исправить блокирующие ошибки модели заказов, склада, финансов и доступа до production-релиза.

## Что изменено в RC1

### Заказы
- Один заказ поддерживает несколько товарных позиций через `order_items`.
- Интерфейс заказа позволяет добавлять и удалять строки товара.
- Добавлен расширенный жизненный цикл: Новый → Подтверждён → В производстве → Собирается → Готов → На доставке → Доставлен → Выполнен / Отменён.
- После начала отгрузки состав заказа нельзя тихо переписать: требуются корректирующие операции.

### Склад
- Физический остаток и резерв разделены.
- `on_hand` — фактическое количество на складе.
- `reserved` — количество, зарезервированное под подтверждённые заказы.
- `available = on_hand - reserved`.
- Перевод заказа в «На доставке» превращает резерв в физическую отгрузку.
- История склада append-only: старые движения не переписываются.

### Финансы
- Заказ сам по себе больше не считается выручкой.
- Реализация признаётся только после доставки/выполнения.
- Оплата и возврат денег — разные события.
- Уменьшить полученную оплату редактированием заказа нельзя; возврат оформляется отдельной операцией.
- Финансовый журнал append-only.

### Доступ
- Самостоятельное создание новых организаций из браузера отключено.
- Новые сотрудники подключаются к существующей IceFresh только по приглашению владельца.
- Финансовые KPI не показываются роли `staff`.

### AI
- Добавлен серверный `AI Provider Gateway`.
- Архитектура поддерживает OpenAI, Anthropic/Claude, Google Gemini и HTTPS OpenAI-compatible endpoint.
- Все ключи остаются серверными секретами.
- Custom endpoint проверяется: только HTTPS, без localhost и приватных сетей.

### PWA
- Версия кеша повышена до `icefresh-rc1-v21`.
- RC отмечен как `published: false`.

## Что НЕ сделано автоматически

1. RC1 не применён к боевой Supabase.
2. Публичный домен icefresh.kz не переключён.
3. Дублирующая организация IceFresh в рабочей базе не удалялась — перед production нужно подтвердить, какой профиль владельца является основным.
4. Supabase Leaked Password Protection нужно включить в настройках Auth.
5. SECURITY DEFINER warnings по `accept_invite` и `manage_member` требуют финального review/justification; они имеют серверные проверки прав, но advisor всё равно предупреждает о повышенных привилегиях.
6. WhatsApp Business Platform архитектурно подготовлен через outbox/channel, но реальные Meta credentials/webhook ещё не подключены.
7. Полный browser E2E и тест на реальных iPhone/Android должны выполняться после staging-migration.

## Проверки в этой RC-сборке

Успешно выполнено:
- `node --check public/app.js`
- `node --check public/core.js`
- TypeScript-проверка `worker/ai-provider.ts` + `worker/ai-assistant.ts` без внешних типов
- 9 статических/route regression tests — 9/9 пройдено
- grep-аудит на секретные OpenAI ключи в клиентском коде

Полный `npm test` в этой сессии не запускался, потому что среда не имела доступ к npm registry и зависимости исходного ZIP не содержали `node_modules`. В CI/staging требуется выполнить `npm ci && npm test && npm run lint`.

## Production gate

Порядок перед публикацией:

1. Выбрать основную организацию IceFresh и безопасно решить судьбу пустого дубля.
2. Сделать backup рабочей Supabase и проверить возможность восстановления.
3. Применить RC migration на staging/копии базы.
4. Проверить `order_items`, stock ledger, RLS, grants и RPC.
5. E2E: производство → заказ из нескольких позиций → подтверждение → резерв → отгрузка → доставка → оплата → возврат оплаты → проверка ledger.
6. Проверить конкурирующие заказы с двух устройств — отрицательный available не допускается.
7. Проверить owner/admin/staff права.
8. Проверить iPhone/Android/PWA update/offline states.
9. Запустить Supabase Security + Performance Advisors.
10. До smoke-test задать Worker-переменную `ICEFRESH_ORGANIZATION_ID` равной UUID канонической организации IceFresh. Публичные Contacts/catalog работают fail-closed без валидного UUID.
11. Только после зелёного отчёта сохранить production version и отдельно подтвердить deploy на icefresh.kz.
